01

问题与方法

要解决的问题

不熟悉技术的音乐学习者，怎样分别调整音高与速度，同时保证原始音频不被改动？

采用的方法

FFmpeg/FFprobe 与 Rubber Band 负责音频检查、变调和变速。我让处理在后台运行，并把取消、文件名冲突与残缺输出作为应用需要处理的正常分支。源文件保持不变，输出文件通过独占创建避免覆盖已有文件。

02

我的贡献

  1. 01

    两个平台的独立开发

    原 Windows 应用与 Apple Silicon macOS 版本均由我独立开发。2026 年 8 月，我在 3 天内交付经过测试和打包的 macOS 预发布版。

  2. 02

    分别调整调性与练习速度

    我实现 -24 至 +24 半音的变调和 -95% 至 +400% 的变速，两项参数可独立设置，支持 MP3、M4A、WAV 和 FLAC 输入。

  3. 03

    取消后完成清理

    我加入后台处理、子进程组清理、不覆盖现有文件的独占输出创建、源文件保护，以及失败或取消时的残缺文件删除。

  4. 04

    主动验证失败场景

    我的测试覆盖参数校验、文件系统冲突、故障注入、实际音频处理、打包后执行、取消、清理、源文件保护和界面行为。

  5. 05

    可以分发的预览版

    我将 Python 与音频工具打包，审计本地二进制和库引用，在另一台非开发 Mac 上验证，并准备许可证、对应源码、校验和及公开预览版。

03

应用如何处理实际使用中的问题

  1. 01

    分别选择调性与练习速度

    MP3、M4A、WAV、FLAC 输入支持 -24 至 +24 半音与 -95% 至 +400% 的速度调整。

  2. 02

    在后台完成处理

    FFmpeg 与 Rubber Band 执行音频处理时，界面仍保持响应。

  3. 03

    文件冲突时保留已有内容

    遇到已有输出时，以数字后缀分配新文件，并通过独占创建防止覆盖冲突。

  4. 04

    取消时终止进程并清理

    终止相关子进程组，清理残缺输出。发布检查中，源文件保持不变，也没有遗留残缺文件。
