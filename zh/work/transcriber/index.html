01

问题与方法

要解决的问题

学生怎样使用设备本地转写跟上课堂讲授，而不依赖云端转写服务或事先配置的开发环境？

采用的方法

应用通过 whisper.cpp 与 Metal 在本机运行 Whisper。重叠音频片段保持连续采集，也可能在片段边界产生重复文本。我先保存原始输出，再谨慎清理重复，并将两个版本与会话日志、配置一同保存。采集和推理通过异步工作线程运行，使界面保持响应。

02

我的贡献

  1. 01

    本地音频处理管线

    我用异步工作线程处理采集与推理，让音频处理时界面保持响应。麦克风音频经过缓冲，从 48 kHz 重采样为 Whisper 使用的 16 kHz 格式。

  2. 02

    模型下载与管理

    我加入模型扫描、导入、选择和下载管理，通过精确文件大小与 SHA-256 检查、临时下载、重试处理和原子发布，避免损坏模型被当成可用文件。

  3. 03

    保留原文，也提供可用文本

    我在片段边界去重之前保存后端原始输出。用户可以将整理后的文本与原文对照，同时查看模型、语言、日志和会话配置。

  4. 04

    应用打包与发布

    我将 Python 与本地库打包为可独立运行的 macOS 应用，固定构建依赖，并测试应用包中的推理流程。

03

应用如何处理实际使用中的问题

  1. 01

    加载经过完整性检查的模型

    下载文件先保存在临时位置，通过大小与 SHA-256 检查后才可用，也可以导入本地模型。

  2. 02

    转写时保持界面响应

    音频采集与本地推理异步运行，重叠片段送入 Metal 加速的后端。

  3. 03

    原始文本与整理文本并存

    每个会话保存 raw.txt、clean.txt，以及 session.log 和 config.json，便于将清理后的文本与后端输出对照。

  4. 04

    继续使用已保存的会话

    增量复制、安全重命名与完整历史恢复都基于保留的会话输出进行。
